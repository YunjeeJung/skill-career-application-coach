- 기업 지원 통합 관리: `collection://69ec50a6-c540-451d-b450-ea718304c413`

이 ID들은 현재 연결된 `윤지 정의 Notion` 워크스페이스의 원본이다. 이름 검색으로 비슷한 DB를 대신 사용하지 않는다. 호출이 실패하면 원본 페이지를 검색해 현재 data source URL을 확인한다.

## 읽기 절차

1. 연결 상태가 확인되지 않았다면 Notion의 `self`를 조회한다.
2. 각 작업 세션에서 사용할 data source를 먼저 fetch하여 현재 스키마를 확인한다.
3. Experience Master는 data source query로 후보를 좁힌다. 텍스트의 서식·링크·멘션이 중요하거나 실제 제출 문장을 만들 때는 후보 페이지도 fetch한다.
4. 결과가 없다고 단정하기 전에 경험명, 업무 영역, 핵심 역량 태그, 지원 직무 연결, 회사/브랜드를 조합해 검색한다.

## Experience Master 필드

핵심 사실 필드:

- `경험명`, `회사/브랜드`, `기간`
- `육하원칙`, `성과`, `역량`
- `Situation`, `Task`, `Action`, `Result`
- `KPI·정량성과`, `기여도`
- `업무 영역`, `핵심 역량 태그`, `지원 직무 연결`
- `데이터 신뢰도`: `확정` / `확인 필요` / `추정`
- `대표 경험`
- `정리 상태`: `인덱스` / `보강 필요` / `정리 완료`

`정리 완료`는 Situation, Task, Action, Result가 독립된 정보로 있고, 본인의 판단 또는 실행과 사실 기반 Result가 명확하며, 필요한 태그와 수치 신뢰도가 정리됐을 때만 사용한다.

지원 직무 태그는 `플랫폼 MD`, `패션 기획MD`, `커머스 PM`, `AI/DX PM`, `IP 사업기획`, `사업기획/전략`, `Product Ops/BA` 중 현재 스키마에 존재하는 값을 사용한다.

## 쓰기 절차

- 수정 전 해당 페이지를 fetch하고, 바꿀 필드와 값을 사용자에게 요약한다.
- 사용자에게 저장 요청이 이미 있으면 별도 재승인 없이 요청 범위 안에서 수정할 수 있다. 그렇지 않으면 요약 후 승인을 기다린다.
- 사용자가 확인한 값만 기록한다. 확실한 수치는 `확정`, 검증이 필요한 수치는 `확인 필요`, 가설성 값은 `추정`으로 둔다.
- 페이지 속성은 현재 fetch 결과의 정확한 이름과 허용 옵션을 사용한다. 읽기 전용 속성은 수정하지 않는다.
- 수정 후 페이지를 다시 fetch해 값이 반영됐는지 확인한다.

## 기업 지원 통합 관리

이 DB는 `기업명`, `지원 포지션`, `공고 링크`, `지원 마감일`, `지원 상태`, `현재 전형`, `다음 일정`, `다음 할 일`, `제출 서류 버전`, `결과 메모` 등을 관리한다. 사용자가 기록을 요청하거나 기존 지원 건을 함께 관리하기로 승인했을 때만 생성·수정한다. JD 요약과 추천 경험처럼 스키마에 없는 긴 분석은 해당 기업 페이지 본문에 추가하되 기존 본문을 보존한다.
