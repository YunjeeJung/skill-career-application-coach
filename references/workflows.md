# 워크플로

## Experience Builder

Experience Master에서 관련 경험을 찾아 `육하원칙`, `성과`, `역량`, STAR, KPI를 모두 읽는다. 확보된 사실과 누락을 구분하고 Situation, Task, Action, Result, KPI, 기여도 중 중요한 누락만 1~3개씩 질문한다.

사용자의 답을 반영한 초안을 다음 순서로 보여준다.

- 경험 한 줄 요약
- Situation / Task / Action / Result
- 핵심 KPI
- 증명되는 역량
- 활용하기 좋은 지원 직무
- 추가 확인이 필요한 정보

사용자가 확인하고 저장을 요청하면 Experience Master를 업데이트한다. 충분하면 `정리 완료`, 아니면 `보강 필요`를 유지한다.

## JD Matcher

채용공고 텍스트, 이미지, PDF, URL 또는 사용자의 설명에서 다음을 분리한다.

- 주요 역할
- 필수 요건과 우대 요건
- 반복되는 핵심 키워드
- 기대되는 성과 영역

공고에 여러 직무가 있으면 실제 업무와 요구 역량을 비교한다. Experience Master에서 가장 활용도 높은 경험 3~5개를 고르고 부족한 요구 역량도 함께 제시한다.

출력:

1. JD 핵심 요약: 역할, 핵심 역량, 우대 요소
2. 경험 매칭 표: 경험 / 연결되는 JD / 강조 포인트 / 보완 필요
3. 이번 지원의 핵심 포지셔닝 한 문장
4. 경력기술서 우선 사용 경험 1~3순위

공고 URL처럼 최신성이 있는 자료는 가능하면 원문을 확인하고, 접근할 수 없으면 사용자가 제공한 내용만 분석했다고 밝힌다.

## Cover Letter Planner — 필수 승인 게이트

완성 문장을 쓰기 전에 반드시 아래 세 단계만 수행한다.

1. 문항 분석: 확인 의도, 평가 역량, JD 연결, 피해야 할 방향
2. Experience Master 후보 최대 3개: 추천 이유, 사용할 근거·KPI, 강조 역량, 약점·추가 확인
3. 추천 전략: 추천 경험, 핵심 메시지, 구성 비중, JD 연결, 차별화 포인트

마지막에 "이 방향으로 초안을 작성할까요?"처럼 구체적으로 확인하고 멈춘다. 이 답변에는 제출 가능한 완성 문단이나 사실상 완성본인 긴 예시를 포함하지 않는다.

사용자가 다른 경험을 원하면 전략을 갱신하고 다시 승인받는다. 여러 문항이면 문항별 경험 중복도 함께 보여주고, 각 문항의 방향을 승인받는다.

## Cover Letter Writer

Planner에서 제안한 경험과 핵심 메시지가 승인된 경우에만 실행한다. Experience Master와 JD에서 확인된 사실만 사용하고 글자 수 제한을 맞춘다.

- 첫 문장에서 결론이나 강점이 드러나게 한다.
- `왜 했는가 → 무엇을 판단했는가 → 어떻게 실행했는가 → 결과` 흐름을 우선한다.
- JD 표현을 복사하지 말고 실제 경험과 연결한다.
- 동일 지원서의 다른 문항과 경험이 과도하게 겹치지 않게 한다.
- 없는 수치나 역할은 빈틈을 메우기 위해서도 만들지 않는다.

초안 뒤에는 `사용한 Experience Master 경험`, `핵심 메시지`, `문항 연결 논리`, `사실 확인 필요 문장`을 짧게 덧붙인다. 확인이 필요한 문장은 제출본과 명확히 분리한다.

## Career Resume

지원 JD 또는 목표 직무로 Experience Master를 필터링하고 경험을 지원 직무에 맞는 순서로 재배열한다. 각 프로젝트를 `프로젝트명 / 목표·문제 / 핵심 행동 / 성과 / 역할·기여도`로 압축한다. 원본 사실은 유지하고 표현과 강조점만 조정한다. 기존 경력기술서가 제공되면 중복과 누락을 비교한다.
